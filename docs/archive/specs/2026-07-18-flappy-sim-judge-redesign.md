# Flappy Race — 시뮬레이션 판정 재설계 (Sim Judge Redesign)

**목표:** 맵 밸런싱을 신뢰 가능하게 만들기 위해, "통과 가능?"과 "얼마나 어려움?"을 서로 다른 두 도구로 분리 판정한다.

## 배경 / 문제

기존엔 단일 탐욕(greedy) 봇 하나로 두 질문을 동시에 판정 → 둘 다 왜곡됨.
- **가능성 봇** ("틈 바닥 근처면 플랩")은 좁은 틈에서 아치로 오버슛 → *물리적으로 넘을 수 있는* 틈을 "불가능"으로 오판 → 틈을 과하게 넓힘 → 맵이 쉬워짐.
- **사람 봇**(조준오차 기반)은 사람의 실제 오차원(타이밍)이 아니고, 넓은 틈 구간만 돌려 "난이도 평평" 오결론.

핵심 결함: **봇 한 마리의 제어 실력 = 판정 기준**이 되어, 봇이 서투르면 맵을 쉽게 만들고 봇 실력 밖은 못 봄.

## 도구 A — 통과 가능성 (상태공간 도달성 탐색)

헤드리스 시뮬(`execute_code`)로 코스 콜라이더를 읽어 실제 물리로 전방 탐색.

- **상태** = 이산화된 `(y, vy)`. y 0.1 단위, vy 1 단위(범위 −maxFall … +flapImpulse).
- **전진** dx=0.1. 각 상태 두 분기: 플랩(vy=flapImpulse) / 안함(vy 유지) → `vy -= gravity·dt; y += vy·dt` (dt=dx/forwardSpeed), maxFall 클램프.
- 새 `(x,y)`가 벽·천장·바닥과 birdR 안에서 겹치면 상태 제거.
- 생존 상태를 `(y,vy)` 이산 키로 중복 제거(상태 폭발 방지).
- **끝까지 생존 상태 ≥1 → 경로 존재 = 통과 가능** (봇 실력 무관, 참 물리 한계).
- 각 게이트 생존 상태 수 = **회랑 여유폭** → 가장 좁은 게이트 식별.

## 도구 B — 체감 난이도 (타이밍 지터 몬테카를로, 3단)

반응형 제어(다가오는 틈에만 반응) + **타이밍 오차만**으로 실력별 200마리씩.

| 실력 | 반응지연 | 타이밍지터 | 예측범위 |
|------|---------|-----------|---------|
| 초보 | 0.20s | ±0.08s | 0.4s |
| 중수 | 0.13s | ±0.05s | 0.6s |
| 고수 | 0.08s | ±0.03s | 0.9s |

- 봇은 조준하지 않고 "이대로 가면 틈 바닥 밑으로 빠질" 예측 시 플랩(반응지연+지터).
- **산출**: 실력별 생존율 + 게이트별 사망 히트맵.

## 밸런싱 기준

1. 도구 A = **경로 존재 필수** (없으면 불통 맵 → 리젝).
2. 도구 B = **고수 생존율 높음 / 초보 낮음**, 사이는 완만한 곡선.
3. 특정 게이트만 사망 스파이크 없어야(의도한 난관 제외).

## 비범위 (YAGNI)

- 새 몬테카를로/탐색은 헤드리스 순수 계산. 화면 재생(FlappyAutoPilot)은 별개로 유지.
- 대시·몸싸움·네트코드 미포함.
