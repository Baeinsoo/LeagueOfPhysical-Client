# 플레이어 신원 — 표시 이름 + 태그 설계

유저가 자기 이름을 정할 수 있게 하고, 화면이 `Guest-05a6f594-8cac-...` 대신 사람이 읽을 수 있는
신원을 보여주게 한다.

---

## 1. 왜 지금

방금 결과 화면과 전적 목록을 만들었는데, **거기 뜨는 상대가 `Guest-05a6f594`다.** 만든 화면이 제 값을
못 하고 있다. 전적은 "누구와 무엇을 했나"의 기록인데 "누구"가 uuid면 기록의 절반이 비어 있는 셈이다.

---

## 2. 지금 상태 — 이름 자리는 이미 있다, 정체가 어긋나 있을 뿐

`User.username`은 **로그인에 쓰이지 않는다.** 로그인은 `UserIdentity(provider, providerUserId)`가 한다.
`username`은 가입 때 `Guest-<uuid>`로 채워지고, 실제로 읽는 곳은 **딱 하나** — 매치 확정이 전적 문서의
`displayName`을 채울 때다(`match-result.dao.postgres.ts`).

즉 **이미 표시 이름 자리**인데 이름이 `username`이고 `@unique`가 붙어 있다. 새 개념을 더하는 게 아니라
정체를 바로잡는 일이다.

---

## 3. 결정 — 이름은 자유, 유일성은 태그가 진다

```prisma
model User {
  id          String   @id @default(uuid())
  displayName String              // 자유·중복 허용. 형식 검증만
  tag         String   @unique    // 가입 때 부여, 이후 불변
  email       String?  @unique
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  lastLoginAt DateTime?
}
```

화면 표기: **`철수#K7QM2X`**

- `displayName`: 유일 제약 **없음**. 클라의 전적 DTO가 이미 이 이름을 쓰고 있어 어휘가 맞는다
- `tag`: **Crockford Base32 6자리**, 전역 유일, 계정에 고정 — 유저·운영자 모두 못 바꾼다
- `username` 컬럼은 `displayName`으로 **개명**하고 `@unique`를 뗀다(새 컬럼 추가가 아니다)

### 이 조합이 주는 것

**개명이 절대 거절되지 않는다.** 태그가 이미 유일하므로 `이름#태그`도 자동으로 유일하다. 이름에
유일성 검사가 필요 없고, "그 이름은 이미 사용 중입니다"라는 응답 자체가 존재하지 않는다.

---

## 4. 왜 이 모양인가 — 업계 조사 (2026-08-21)

### 4-1. 표시 이름을 유일하게 두지 않는 것이 현재 다수파

| 플랫폼 | 표시 이름 중복 | 유일성을 지는 것 |
|---|---|---|
| Riot (2023~) | 허용 | `이름#태그라인` 조합 |
| Battle.net | 허용 | `이름#1234`(숫자 자동 부여) |
| Roblox (2021~) | 허용 | 별도 `username`(로그인용) |
| Discord (2023~) | 허용 | 별도 `@username` |
| Xbox | 허용 | 겹치면 `#1234` 자동 접미 |
| Steam | 허용 | 로그인용 계정명(별개) |
| PlayStation | **불가** | Online ID 자체 |

PSN만 옛 방식이고 나머지는 다 넘어갔다. **Riot이 넘어간 이유가 우리에게 그대로 적용된다** —
신규 유저가 안 겹치는 이름을 찾느라 열 번 가까이 시도하고 있었다.

### 4-2. 그런데 "대세"는 하나가 아니다 — 2023년에 두 회사가 반대로 움직였다

| | 어디서 어디로 | 이유 |
|---|---|---|
| **Riot** | 유일 이름 → `이름#태그` | 이름 선점이 아팠다 |
| **Discord** | `이름#1234` → 유일 핸들 + 자유 표시명 | 태그 때문에 **절반이 연결에 실패**했다 |

각자 자기가 아픈 데서 도망쳤다. 갈림은 **"이름 선점이 아픈가, 사람 찾기가 아픈가"** 로 결정된다.

**우리는 사람 찾기 기능이 없다**(친구 추가·초대·이름 검색 전부 없음. 매칭은 시스템이 붙인다).
그러니 Discord가 도망친 문제는 아직 존재하지 않고, Riot이 도망친 문제만 남는다 → 태그 방식이 맞다.

### 4-3. 태그를 계정에 고정하되 **전역 유일**로 (Battle.net과 다른 지점)

두 갈래가 있었다:

| | 태그 유일성 | 개명 거절 | 계정 수 한계 |
|---|---|---|---|
| **조합 유일** (Battle.net·Riot) | 없음 | **있음**(`철수#0421`이 이미 있으면 거절) | 없음 |
| **태그 자체 유일** ← 채택 | 있음 | **없음** | 태그 공간 |

태그가 계정에 고정되면서 조합만 유일하면, 개명 시 드물게(1/10000 수준) 거절이 난다 — 설명하기 어려운
실패다. **태그를 전역 유일로 두면 그 실패가 구조적으로 사라진다.** 대가는 태그 공간이 계정 수 상한이
되는 것인데, 아래 알파벳으로 해소된다.

### 4-4. 알파벳 — Crockford Base32

사람이 불러주고 받아적는 코드라 알파벳 선택에 정석이 있다. **Crockford Base32**는 숫자 10 + 알파벳 22
(**`I`·`L`·`O` 제외** — 1과 0으로 헷갈려서, **`U` 제외** — 우연히 욕이 되는 걸 줄이려고)로,
읽을 때 대소문자를 안 가리고 `i`/`l`→`1`, `o`→`0`을 자동 보정한다.

> **대소문자 구분을 피하는 것이 중요하다** — 디스코드가 태그를 버린 이유 중 하나가 *대소문자 구분
> 때문에 절반이 연결에 실패*한 것이었다. 62자를 다 쓰면 가짓수는 크지만 사람이 쓰기 나빠진다.

### 4-5. 자릿수 — 6

| | 가짓수 | 계정 10만일 때 무작위 한 번에 실제 계정을 맞힐 확률 |
|---|---|---|
| 5자리 | 3,355만 | **1/335** |
| **6자리** | **10억 7천만** | **1/10,737** |

용량은 둘 다 남아돈다 — **판단 근거는 열거 저항이다.** 태그가 나중에 친구 추가에 쓰이면 밖에
알려주는 식별자가 되고, 5자리면 335번만 찍어도 남의 계정이 걸린다. 6자리는 32배 낫다.
덤으로 `K7Q-M2X`처럼 **3-3으로 끊어 읽을 수 있다**(5자리는 3-2라 어정쩡하다).

---

## 5. 태그 부여

가입 시 무작위 6자리를 뽑아 넣고, **유일 제약에 걸리면 다시 뽑는다**(최대 5회, 초과 시 에러).

> 미리 조회해서 빈 걸 찾는 방식(check-then-insert)은 **경합에서 뚫린다** — 두 요청이 같은 빈 태그를
> 동시에 보고 둘 다 쓴다. 유일성은 DB 제약이 지고 코드는 실패를 재시도할 뿐이다.
> `[[invariant-as-primary-key]]`

계정 10만 개에서 한 번에 충돌할 확률이 1/10,737이라 재시도는 사실상 안 일어난다.

**저장 형태**: 대문자 정규화(`K7QM2X`). 조회 시 입력을 Crockford 규칙으로 보정 후 비교(지금은 조회
기능이 없으므로 보정 함수만 두고 쓰는 곳은 나중에).

---

## 6. 기본 이름

가입 시 `displayName = "플레이어"`. 모두 같은 이름이고 **태그가 가른다** — `플레이어#K7QM2X`.
이름에 유일 제약이 없으므로 몇 명이든 상관없다.

---

## 7. 개명

```
PUT /user/display-name      { "displayName": "철수" }      (본인만)
```

- 형식: **2~12자**, 앞뒤 공백 제거 후 검증, 공백·제어문자 금지
- 유일성 검사 **없음** — 거절 사유는 형식 위반뿐
- 변경 횟수·기간 제한 **없음**(이름이 희소 자원이 아니므로 제한할 이유가 없다)
- 욕설 필터는 **범위 밖**

신규 응답 코드: `INVALID_DISPLAY_NAME = 30001` (`USER_NOT_EXIST = 30000` 옆).

---

## 8. 전적에 박히는 값

`Match.result[].displayName`에 **`이름#태그` 통째로** 저장한다(`철수#K7QM2X`).

지난 트랙에서 만든 성질을 그대로 쓴다 — 확정 시점 값을 박아 두므로 **개명해도 과거 전적은 안 바뀐다.**
이름만 저장하면 그때 누구였는지가 흐려진다(동명이인 구분 불가).

---

## 9. 화면

| 화면 | 표시 |
|---|---|
| 프로필 | 상단에 `철수#K7QM2X` + **이름 바꾸기** |
| 전적 목록 | 참가자 줄에 `철수#K7QM2X`(본인은 "나") |
| 결과 화면 | 지금 그대로 — 이름 정보가 와이어에 없다. **범위 밖**(§11) |

프로필의 이름 바꾸기는 입력 + 확인. 실패는 형식 위반뿐이라 안내 문구도 하나다.

## 10. 슬라이스

| | 무엇 | 어디 | 끝났다는 기준 |
|---|---|---|---|
| **1** | 스키마 + 태그 부여 + 개명 라우트 | 백엔드 (+마이그레이션) | 가입하면 태그가 붙고, 개명이 된다. **화면 변화 없음** |
| **2** | 클라 — 프로필에 신원 표시 + 이름 바꾸기 | 클라 | 프로필에서 이름을 바꾸면 전적에 새 이름이 뜬다 |

---

## 11. 범위 밖 (의도)

- **결과 화면의 이름** — 와이어(`MatchEndedToC`)에 이름이 없다. 넣으려면 proto를 고쳐야 하고, 결과
  화면은 이미 "플레이어 N"으로 동작한다. 다음 슬라이스에서 필요해지면 그때
- **친구 추가·태그로 찾기** — 태그를 만드는 것이 이번 범위. 쓰는 기능은 별개
- **욕설 필터 · 이름 검색 · 변경 이력**

---

## 12. 테스트

| 대상 | 방법 |
|---|---|
| 태그 생성 | 단위 — Crockford 알파벳만 나오는가(`I`·`L`·`O`·`U` 없음), 길이 6, 대문자 |
| 태그 유일성 | 통합 — 같은 태그를 두 번 넣으면 두 번째가 실패한다(DB 제약이 진다) |
| 재시도 | 단위 — 첫 시도가 충돌하면 다시 뽑는다 / 5회 초과면 던진다 |
| 개명 | 통합 — 형식 위반 거절, **같은 이름을 여럿이 써도 성공**, 남의 이름 변경은 403 |
| 그때 이름 | 통합 — 확정 후 개명해도 전적의 이름은 안 바뀐다(기존 테스트가 이미 고정) |
| 끝‑끝 | 프로필에서 개명 → 새 판 → 전적에 새 이름, 옛 판엔 옛 이름 |
