# Skydive 대기 — 하늘·안개·구름

Skydive 모드의 배경 아트 방향. 목표는 젤다 왕국의 눈물의 낙하 장면 느낌이되,
**환경만** 그 방향으로 가고 캐릭터 셰이딩은 이번 범위 밖이다.

## 1. 왜 — 지금 문제

3000m를 떨어지는데 **화면에 스쳐 지나가는 것이 아무것도 없다.** 결과가 둘이다.

- **속도가 안 읽힌다.** 대자(60)와 다이브(90)를 눈으로 못 가른다. 그래서 HUD에 숫자를
  띄웠는데(`Motion: Skydiving fall 58.2`), 그건 UI로 때운 것이지 근본이 아니다.
- **레이저를 설계할 배경이 없다.** 굵기·색·경고 연출은 뒤에 무엇이 있느냐에 달렸다.
  하늘을 안 정한 채 레이저를 만들면 하늘을 정하고 나서 다시 만지게 된다.

그래서 레이저(슬라이스 4)보다 이것이 먼저다.

## 2. 레퍼런스에서 읽은 규칙

실제 스크린샷 두 장을 보고 뽑았다. 그림을 그림이게 만드는 것은 다섯 가지다.

| 관찰 | 규칙 |
|---|---|
| 먼 지형이 하늘색과 거의 같은 값으로 씻김 | **대기 원근이 아주 강하다** |
| 지평선이 크림빛으로 밝고 위로 갈수록 파래짐 | 세로 그라데이션 |
| 구름이 플레이어 **아래**에 층으로 깔림 | 깊이 단서 = 속도 단서 |
| 가까운 지형만 따뜻한 사암색으로 선명 | **근경 따뜻 / 원경 차갑게** |
| 그림자가 거의 없고 전체가 밝음 | 하이키 |

**핵심은 안개 하나가 아니라 대비다.** 회색 선반이 회색 안개로 씻기면 아무 일도
일어나지 않아 보인다. 근경이 따뜻해야 원경이 씻긴 것이 보인다.

## 3. 스파이크에서 확인한 것 (2026-09-03)

파일을 하나도 안 바꾸고 에디터 메모리에서만 값을 넣어 캡처해 판정했다.

### 3.1 안개 곡선

`ExponentialSquared`, 밀도 **0.0013**. 플레이어가 코스 위에 있을 때:

| 거리 | 씻김 | 무엇이 보이나 |
|---|---|---|
| 150m | 4% | 발밑 선반 — 선명 |
| 400m | 24% | 다음 선반 — 뿌옇게 |
| 1000m | 81% | 거의 하늘색 |
| 3000m | 100% | 바닥 안 보임 |

밀도를 0.00075로 낮췄을 때는 **안개를 끈 것과 눈으로 구분이 안 됐다**(600m에서 18%).
값이 이 근처여야 효과가 있다.

### 3.2 ⚠️ 선반은 깊이 단서가 못 된다

수직으로 내려다본 캡처에서 드러났다 — **위 선반이 아래를 완전히 가린다.** 코스는
200m 폭이라 400m 아래 선반은 보이지 않는다. "선반이 겹겹이 안개 속으로 멀어지는"
구도는 **플레이 중에 나오지 않는다.**

**그래서 낙하 속도감은 구름이 전담한다.** 구름은 장식이 아니라 이 설계의 핵심 부품이다.

### 3.3 부수 발견 셋

| | |
|---|---|
| `SkydiveMap.unity`에 **조명이 하나도 없다** | 빛은 `Skydive.unity`에 있다. 맵만 열면 앰비언트뿐 |
| `Assets/Art/Skybox/skybox.mat`이 **분홍 노을 큐브맵** | 낮 하늘이 아니다 |
| 선반·기둥이 `floor.mat`을 그대로 씀 | 색을 따로 못 준다 (`SkydiveCourseBuilder.cs:83`) |

## 4. 만드는 것

### 4.1 안개

`SkydiveMap.unity`의 렌더 설정에 `ExponentialSquared` ρ=0.0013. 색은 아래 4.2가 정한다.

### 4.2 고도 색조 — 얼마나 내려왔는지가 하늘로 읽힌다

클라 전용 컴포넌트가 내 캐릭터의 높이를 매 프레임 읽어 하늘색과 안개색을 보간한다.

```
3000m   맑고 옅은 파랑        (공기가 얇은 느낌)
1500m   중간
   0m   따뜻한 크림빛 아지랑이 (지면 근처)
```

- **시뮬을 건드리지 않는다** — 월드에서 높이를 *읽기만* 한다(연속 상태는 pull,
  `world-core-connection-architecture.md`의 규칙 그대로).
- 색 보간은 **순수 함수**로 분리해 EditMode로 시험한다(§7).
- HUD 숫자 없이도 진행도가 읽히는 것이 이 항목의 값이다.

### 4.3 구름 층 — 보이는 것과 가리는 것을 나눈다

| | 방법 |
|---|---|
| **보이는 것** | 그 높이에 놓인 반투명 판때기 — 밖에서 보면 층으로 보인다 |
| **가려지는 것** | 층 안에 있는 동안 **안개 밀도를 올린다** |

**전체화면 오버레이를 쓰지 않는 이유** — 안개를 올리면 "가까운 것은 보이고 먼 것은
사라지는" 그림이 저절로 나온다. 채택한 방식(윤곽은 비쳐 보임)이 정확히 그것이다.
오버레이는 가까운 것까지 똑같이 덮어서 "완전히 가림"이 되어 버린다.

층 간격은 약 170m에서 시작한다(3000m에 18층). 낙하 60m/s면 층 사이가 ~2.8초다.

### 4.3.1 안개를 누가 쓰는가 — 값을 갈라 둔다

안개에 쓰는 쪽이 둘이라 소유권을 나눠 둔다. 안 그러면 서로 덮어쓴다.

| 값 | 주인 | 근거 |
|---|---|---|
| `fogColor` | **고도 색조**(§4.2) | 높이에 따라 변한다 |
| `fogDensity` | **구름 층**(§4.3) | 층 안에서 올라갔다 나오면 돌아온다 |

밀도의 기준값(§3.1의 0.0013)은 씬에 저장된다. 구름은 그 기준에 **배수를 곱하고**,
층을 벗어나면 기준으로 되돌린다 — 자기가 마지막에 쓴 값을 기억하지 않는다(그러면
층을 연달아 지날 때 값이 누적된다).

### 4.4 선반을 사암색으로

새 머티리얼을 만들고 `SkydiveCourseBuilder`가 그것을 물리게 한다. §2의 "근경 따뜻"이자,
안개가 실제로 보이게 만드는 조건이다.

## 7. 검증

아트는 유닛테스트가 안 된다. 시험할 수 있는 것만 정직하게 나눈다.

| 대상 | 방법 |
|---|---|
| 고도 → 색 곡선 | **EditMode 테스트.** 3000/1500/0m에서 기대 색. 순수 함수라 가능 |
| **구름에 콜라이더가 없다** | 구운 맵을 훑는 EditMode 검사 (§8 함정) |
| 안개·색 값 | 코드가 아니라 설정이라 테스트 대상이 아니다 |
| 실제 그림 | **고정 시점 캡처를 메뉴로** 만들어 전/후 비교 (스파이크에서 쓴 방식) |
| 시뮬 무영향 | 두 클라 실플레이 — 러버밴딩이 없으면 확인 |
| 모바일 성능 | 폰 빌드로 프레임 측정 |

## 8. 함정 — 미리 박제

| 함정 | 왜 위험한가 |
|---|---|
| **구름에 콜라이더가 붙으면** | 키네마틱 이동이 벽으로 인식해 **구름 위에 착지한다** |
| **`skybox.mat`을 고치면** | FlappyRace · FlapWang · Panchigi · Skydive **네 모드가 같이 바뀐다.** 새로 만들 것 |
| **선반이 기본 머티리얼** | 색을 못 준다. 새 머티리얼 + 빌더 수정이 한 짝 |
| **서브모듈 포인터 커밋 누락** | CI가 옛 맵을 본다 |
| **content-deploy 누락** | 에디터는 멀쩡한데 **폰·서버만 옛 하늘**이 나온다. 어드레서블은 S3에서 온다 |
| **투명 오버드로** | 모바일에서 프레임이 깎인다. 거리 컬링 + 층 수가 첫 손잡이 |

## 9. 배포 사슬

```
① Art 서브모듈 커밋·푸시
② 클라 레포의 서브모듈 포인터 커밋
③ 클라 레포에서 content-deploy (어드레서블)
```

서버는 코드 변경이 없어 재배포가 필요 없다. 단 서버도 맵을 어드레서블로 받으므로
③은 서버에도 영향을 준다 — 구름은 콜라이더가 없어 서버 시뮬에는 무해하다.

## 10. 산업 표준 매핑

- **대기 원근(aerial perspective)** — 회화·게임 공통의 깊이 표현. 거리에 따라 대비와
  채도를 낮추고 배경색으로 수렴시킨다.
- **층으로 놓인 구름 판때기** — 볼류메트릭이 감당 안 되는 플랫폼의 표준 대체(스카이돔
  아래 빌보드/판 레이어).
- **고도에 따른 색조 변화** — 비행·낙하 게임이 진행도를 UI 없이 알리는 관용.
