# 0005. 어드레서블 콘텐츠는 앱과 따로 배포하고, 설치된 앱이 쓰는 콘텐츠는 S3에 추가만 한다

- 상태: Accepted
- 날짜: 2026-07-05 (설계) · 2026-07-09 (검증)
- 관련: `infrastructure/docs/specs/2026-07-05-deployment-system-design.md` §4 ③a·③b · [0003](0003-gitops-argocd-sha-tags.md) · [0004](0004-ci-runner-placement.md)

## 맥락

어드레서블(Unity가 캐릭터 모델 같은 에셋을 번들로 묶어 서버에서 내려받게 하는 기능) 콘텐츠는 앱보다
훨씬 자주 바뀐다. 앱은 코드가 바뀔 때만 새로 내면 되는데, 콘텐츠를 바꿀 때마다 앱을 다시 내고
다시 설치하게 하고 싶지 않았다.

문제는 **이미 설치된 앱**이다. 앱에는 빌드 당시의 카탈로그(어떤 번들이 어디 있는지 적힌 목록)와 일부
번들이 들어 있다. 콘텐츠를 처음부터 다시 구우면(Full build) 번들 이름·해시가 달라져 설치된 앱과
어긋난다. 또 예전 업로드 스크립트는 `aws s3 sync --delete`로 S3를 로컬 빌드 결과와 똑같이 맞췄는데,
이러면 설치된 앱이 아직 가리키는 옛 번들이 지워진다.

## 결정

- 콘텐츠 배포는 앱 배포와 **별도의 버튼(워크플로)** 이다. 서로를 기다리지 않는다.
- 앱을 빌드할 때 그 시점의 `addressables_content_state.bin`(콘텐츠 증분 빌드의 기준점)을 S3의
  앱 빌드별 경로에 보관하고, 최신 빌드를 가리키는 `latest.json`을 갱신한다.
- 설치된 앱이 받는 콘텐츠(Android, iOS)는 그 기준점을 내려받아 **"Update a Previous Build"(증분)** 로
  굽는다.
- 이 콘텐츠의 S3 업로드는 **추가만 한다. `--delete`를 쓰지 않는다.**
- 이 경로는 git·ArgoCD를 거치지 않고 S3로 바로 올린다. 클러스터 배포(0003)와 무관하다.

## 결과

- 앱 재설치 없이 콘텐츠를 갱신할 수 있다(2026-07-09 검증: 증분 빌드 후 추가 업로드로 기존 번들 보존).
- 기준점이 없으면 증분 빌드를 할 수 없다. 앱 배포를 한 번은 먼저 돌려야 콘텐츠 배포가 가능하다
  (없으면 워크플로가 일부러 멈춘다 — 기준점 없이 구운 증분은 설치본과 어긋나기 때문이다).
- 추가만 하므로 쓰지 않는 옛 번들이 S3에 쌓인다. 정리는 별도 과제로 남긴다.
- 설치본이 없는 대상(게임서버용 Linux, 에디터 테스트용 Standalone)은 나중에(2026-09-13) Full build에
  선택적 `prune`(삭제) 옵션을 붙였다. 기본값은 여전히 추가만 하기이고, 설치된 앱용 증분 잡은
  이 옵션을 아예 보지 않는다.
- 버린 대안
  - **콘텐츠를 앱과 함께 배포**: 콘텐츠를 바꿀 때마다 앱을 다시 내야 한다.
  - **매번 Full build + `--delete`로 S3 동기화**: 설치된 앱의 카탈로그가 가리키는 번들이 사라진다.
- 다시 볼 조건: 옛 앱 버전 지원을 끊는 정책(강제 업데이트)이 생기면, 그보다 오래된 번들은 지워도 된다.
