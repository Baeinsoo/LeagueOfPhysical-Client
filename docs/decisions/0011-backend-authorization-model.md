# 0011. 백엔드 인가 모델: 주체별 인가, `/internal`은 키 전용, 볼 수 없는 것은 "없음"으로 답한다

## 맥락

인증 cutover(토큰을 실제로 검사하도록 바꾸는 작업) 전에는 백엔드 라우트 대부분이 무인증이었고, 셋 다 인그레스(외부 요청을 클러스터 안 서비스로 보내 주는 입구)로 밖에 열려 있었다. 누구나 남의 위치를 바꾸고, 방을 만들고 지우고, 죽은 방의 하트비트를 대신 보낼 수 있었다.

막기 어려웠던 이유는 **같은 라우트를 클라와 내부 서비스가 함께 부르는데 필요한 권한이 다르다**는 점이다. 클라는 자기 정보만 읽으면 되지만, 매치메이킹은 상대를 골라야 하므로 모든 유저를 읽어야 한다. 흔한 해법은 "내부용 경로를 따로 만들자"인데, 그러면 같은 조회가 두 벌이 되고 "내부 경로니까 안전하다"는 가정에 기대게 된다.

## 결정

**새 라우트는 반드시 셋 중 하나로 분류하고 그에 맞는 가드를 붙인다.** 무인증 라우트는 새로 만들지 않는다.

| 성격 | 처리 |
|---|---|
| 같은 동작인데 권한 범위만 다르다 | 경로 하나. 호출한 주체(유저인지 서비스인지)를 먼저 가리고(`authenticatePrincipal`), 서비스는 전부, 유저는 자기 것만 허용한다(`requireSelfOrService`) |
| 로그인했는지만 볼 수 있다 (누구 것인지 판정할 수 없다) | 로그인 확인만 (`authMiddleware`) |
| 유저가 부를 이유가 없는 동작 (방 생성·상태·하트비트, 위치 갱신, 토큰 검증 등) | `/internal/*` 경로, 내부 키로만 |

- **가르는 기준은 "동작이 다른가, 권한만 다른가"다.** 권한만 다르면 경로를 나누지 않고 주체별로 인가한다. 서비스 간 호출의 표준(OAuth client_credentials에서 서비스도 같은 엔드포인트를 부르고 권한 범위가 범위를 정하는 방식)을 따른 것이다. **경로를 나누는 것은 권한이 아니라 노출을 다루는 도구**로만 쓴다.
- **`/internal`은 인그레스에서 막는다.** 내부 서비스끼리는 클러스터 DNS(`lobby-server-service` 같은 클러스터 안 이름)로 바로 부르고 인그레스를 거치지 않으므로, 이 차단은 정상 트래픽을 하나도 끊지 않는다. 비용 없이 한 겹을 더 얻는다.
- **주체 판정 규칙**: 내부 키 헤더가 있는데 틀리면 유저 토큰으로 내려보내지 않고 거절한다(내려보내면 키를 떠보는 공격자가 정상 응답을 받고 설정 오류도 숨는다). 키 헤더가 없으면 내부 키 설정값을 아예 읽지 않는다(키 설정이 빠진 서비스에서 유저 조회까지 죽지 않게).
- **볼 수 없는 리소스는 "없는 것"과 똑같이 답한다**(예: 남의 매치 조회). "권한 없음"과 "없음"을 구분해 주면 id를 넣어 보는 것만으로 그것이 있는지 알아낼 수 있다.

## 결과

- 쉬워지는 것: 새 라우트를 만들 때 표 하나로 판단이 끝난다. 같은 조회가 두 벌로 갈라지지 않는다. `/internal`은 클라가 부르지 않으므로 옮겨도 중복이 생기지 않고, 인그레스에서 한 규칙으로 막을 수 있다.
- 어려워지는 것:
  - 서비스끼리 부를 때 모두 키를 붙여야 하고, 키가 필요한 서비스에 키가 빠지면 그 기능이 통째로 멈춘다.
  - 라우터가 모두 앱 루트에 붙는 구조라, 미들웨어를 등록하는 위치와 순서를 틀리면 조용히 앱 전체를 막거나 아무것도 막지 못한다. 가드가 실제로 막는지 테스트로 확인해야 한다.
- **알고 있는 약점**: 내부 키가 **하나뿐**이다. 어느 서비스가 불렀는지 구분할 수 없고 감사 기록도 없다. 키가 새면 모든 내부 동작이 열린다(인그레스는 밖을 막지만 클러스터 안은 막지 않는다).
- 버린 대안:
  - **권한이 다른 조회마다 내부 전용 경로를 따로 만든다**: 같은 동작이 두 벌이 되고, 신뢰를 서비스 신원이 아니라 네트워크 위치에 둔다.
  - **권한이 없으면 403으로 구분해 답한다**: id를 대입해 보는 것만으로 리소스가 있는지 알려 준다.
- 다시 검토할 조건: 서비스별 키를 나누거나 키를 주기적으로 바꾸거나 감사 기록이 필요해질 때(예정된 다음 단계), 또는 외부 파트너가 내부 동작을 불러야 할 때.
