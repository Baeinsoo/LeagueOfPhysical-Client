# 0012. Unity 레포에서는 워크트리 대신 그 자리에서 브랜치를 바꾼다. 플랫폼용 사본만 별도 클론으로 둔다

- 상태: Accepted
- 날짜: 2026-08-14 (iOS 예외는 2026-09-20)
- 관련: `architecture-guidelines.md` §Git 워크플로우의 "작업 시작 시 워크트리를 생성"을 이 ADR이 대체한다

## 맥락

`architecture-guidelines.md`는 작업을 시작할 때 git 워크트리(한 저장소에서 폴더를 하나 더 만들어 다른 브랜치를 동시에 꺼내 두는 기능)를 만들라고 한다. 일반 코드 저장소라면 싸고 편한 방법이다.

Unity 프로젝트에서는 그렇지 않다. 워크트리를 하나 만들면 Unity 입장에서는 프로젝트가 하나 더 생긴다. 사본마다 `Library` 폴더(Unity가 에셋을 가공해 두는 캐시)가 처음부터 새로 만들어지고, 에셋 전체를 다시 가져오는(재임포트) 시간이 든다. 디스크도 사본 수만큼 늘어난다. 피처 하나마다 이 값을 치르면 얻는 것보다 잃는 것이 크다.

그런데 사본이 값을 하는 경우가 하나 있다. 빌드 대상을 iOS로 바꾸면 에셋 전체를 다시 가져오고, 되돌릴 때 또 한 번 가져온다. 본 사본은 macOS 대상으로 두고 다른 작업을 계속해야 하므로, 오가며 매번 재임포트하는 비용이 사본 하나를 따로 두는 비용보다 훨씬 크다.

## 결정

- Unity 레포(LeagueOfPhysical-Client, LeagueOfPhysical-Server)에서는 워크트리를 만들지 않는다. 피처 브랜치는 원래 폴더 안에서 새로 만들어 전환한다. main에 직접 커밋하지 않는다는 규칙은 그대로다.
- 예외: iOS 작업은 형제 폴더 `LeagueOfPhysical-Client-iOS`에 둔 **별도 클론**에서 한다. 본 사본과 같은 `LOP/` 폴더 바로 아래에 둔다(패키지가 `file:../../GameFramework` 같은 상대경로로 형제 레포를 가리키기 때문이다).
- 그 사본을 워크트리가 아니라 클론으로 두는 이유: git 워크트리는 다른 워크트리가 이미 꺼내 둔 브랜치를 꺼낼 수 없다. 플랫폼 사본은 본 사본과 같은 브랜치를 오래 따라가야 하므로 이 제약이 맞지 않는다.
- 예외 2 (2026-09-25): **sparse checkout으로 문서만 꺼낸 워크트리는 허용한다.** git은 파일 일부만 디스크에 꺼내 놓을 수 있다(sparse checkout). `docs/`, `CLAUDE.md` 같은 문서만 꺼내고 `Assets/`는 꺼내지 않으면, 그 폴더는 Unity로 열 수 없어서 `Library`도 재임포트도 생기지 않는다(실측 3.5MB, 본 사본은 3.8GB). 본 사본에서 Unity 작업이 진행 중일 때 그 작업을 건드리지 않고 문서만 고치는 용도다. 끝나면 `git worktree remove`로 지운다.
  ```bash
  git worktree add --no-checkout -b docs/<주제> <경로> origin/main
  git -C <경로> sparse-checkout set --no-cone '/docs/' '/CLAUDE.md' '/README.md' '/.gitignore' '/.claude/'
  git -C <경로> checkout docs/<주제>
  ```
- Unity가 아닌 레포(lop-backend, infrastructure 등)에는 이 제약이 없다.

## 결과

- 쉬워지는 것: 피처마다 재임포트를 기다리지 않는다. 디스크도 늘지 않는다.
- 어려워지는 것: 두 브랜치를 동시에 열어 둘 수 없다. 전환 전에 커밋하지 않은 변경을 먼저 정리해야 하는데, 이 레포에는 Unity가 만든 미커밋 파일이 늘 쌓여 있어 전환이 막히기 쉽다.
- iOS 사본은 따로 pull해야 한다. 형제 레포(GameFramework, Shared 등)는 두 사본이 함께 쓰므로, 한쪽에서 형제 레포를 바꾸면 다른 쪽도 영향을 받는다.
- 버린 대안:
  - **지침대로 피처마다 워크트리**: 위 재임포트·용량 비용 때문에 버렸다.
  - **본 사본 하나에서 플랫폼을 오가며 전환**: 오갈 때마다 전체 재임포트라 버렸다.
  - **iOS용 사본을 워크트리로**: 같은 브랜치를 꺼낼 수 없어 버렸다.
- 다시 검토할 조건: Unity가 사본끼리 가져온 에셋 캐시를 나눠 쓸 수 있게 되어(예: 공유 캐시 서버) 사본 하나 만드는 비용이 작아질 때. Android처럼 다른 플랫폼 사본이 필요해지면 iOS와 같은 방식(형제 클론)을 따른다.
