> **Task 12~15는 그대로 두고, Task 16만 대체**한다.

## 왜 하나

상태이상이 게임 안에서 **보이지 않는다.**

- 헤이스트(id 1)는 이미 동작한다 — 이동속도 +30%. 그런데 화면에 아무 표시가 없어 걸렸는지 알 수 없다.
- 슬로우는 존재하지 않는다. 만들려 해도 못 만든다: 지금 상태이상은 **자기 자신에게만** 걸리고,
  "때린 상대에게 건다"는 수단(`TargetType`)이 없다.
- 클라는 상태이상을 **아예 모른다** — 스냅샷에 실리지 않는다.
- 그리고 **내 캐릭터가 당한 것을 내 클라가 알 방법이 없다** — 아래 "소유자 동기화" 참조.

그래서 "연출을 붙인다"는 목표는 그 앞의 배관(대상 구분 → 데이터 → 복제 → 소유자 동기화)을 먼저 요구한다.

### Task 16이 바뀐 이유

원안은 *"실제 이펙트 에셋이 없으므로 자리와 배선만 만든다. 데이터가 비면 아무 일도 일어나지 않는다"* 였다.
그러면 12~15를 다 만들고도 **눈으로 확인할 수단이 없다.** 사용자 결정(2026-07-26):

> 구조적으로는 완전한 모양이고 리소스만 더미인 상태

즉 **코드 경로는 최종형**, 바꿔 끼울 것은 **에셋 파일뿐**이다.

### 이번에 하지 않는 것

- **머리 위 상태이상 아이콘** — 상태이상이 여러 종류가 되고 "지금 몇 개 걸렸나"를 읽어야 할 때 값을
  한다. 지금은 2종이고 둘 다 이동속도라 몸에 붙는 연출이 더 직관적이다. 나중에 테이블에
  `icon_address` 컬럼을 얹으면 되므로 지금 구조를 막지 않는다.
- **외부 VFX 에셋 도입** — 출시 전 교체할 것이 확정이라 지금 들이는 선택·라이선스·용량 비용이
  회수되지 않는다.
- **지속시간 게이지·스택 표시** — `max_stacks`가 1이라 표시할 것이 없다.

## 설계

### 소유자 동기화 — 내 캐릭터가 당한 것 (신규)

**문제.** 내 클라는 **내 캐릭터만** 시뮬레이션한다(`Simulated` 마커). 그래서 내가 건 효과(헤이스트)는
내가 계산해 안다(예측). 하지만 **남이 나에게 건 효과(슬로우)는 계산조차 하지 않으므로 모른다.**
서버 AI가 플레이어를 공격하므로(`EnemyBrain`) 이 경로는 첫 플레이테스트에서 바로 밟힌다.

결과가 둘이다. 두 번째가 더 크다:

1. 내 몸에 이펙트가 안 뜬다.
2. **서버만 나를 −30%로 움직이고 내 클라는 100%로 예측한다 → 매 틱 위치가 어긋나 러버밴딩.**
   이건 연출을 빼도 발생한다 — `StatusEffectApplyEffect(slow, HitTargets)`를 데이터에 넣는 순간 생긴다.

**해결 — 넉백과 같은 축.** 이미 같은 성격의 것이 하나 있다: **넉백(`MotionContributions`)**.
서버가 가한 것이라 클라가 예측·생성하지 않으므로, `Reconciler`가 **서버 스냅에서 복원**한다
(코드 주석에 그 근거가 명시돼 있다). 상태이상도 정확히 같은 부류다.

- `StatusEffectSystem.ApplyAuthoritativeState(entity, 서버 효과 목록, resolver)` 신설 —
  없는 건 걸고, 사라진 건 떼고, 스택이 바뀌면 다시 계산한다. **스탯 모디파이어까지 함께 맞춘다**
  (모디파이어를 떼는 열쇠 `SourceId = "se:{id}"`는 이미 있다). `HealthSystem.ApplyAuthoritativeState`와
  같은 이름·같은 역할이라 새 어휘가 아니다.
- 호출 지점은 **`Reconciler`의 복원 단계**, `PredictedAbilityState.RestoreTo` **다음**.
  재조정이 예측 상태를 통째로 되돌리므로, 다른 곳에서 적용하면 다음 재조정에 지워진다.
  앵커 틱에서 서버 값이 이기고, 이어지는 재생이 그것을 현재까지 밀어 올린다 — 위치와 완전히 같은 취급.
- 와이어는 **추가하지 않는다.** Task 15가 넣는 `EntitySnap.status_effects`를 원격뿐 아니라
  내 캐릭터(=`Reconciler`로 가는 분기)도 쓰는 것뿐이다.

**이로써 헤이스트와 슬로우의 처리 형태가 같아진다.** 서버 목록이 언제나 진실이고, 예측은 그 위에
얹힌 선반영일 뿐이다 — 헤이스트도 이 동기화를 지나지만 예측이 맞았으므로 아무 일도 일어나지 않는다.
지금은 헤이스트에 확인 절차가 아예 없는 상태라, 이 작업으로 오히려 더 균일해진다.

> 원격 엔티티는 지금처럼 **모디파이어를 적용하지 않는다** — 클라가 시뮬하지 않으므로 필요 없고,
> 느려진 결과는 이미 서버가 보낸 위치·속도에 들어 있다. 원격은 "무엇이 걸렸는지"만 알면 그림을 그린다.

### 데이터 — `TbStatusEffectView`

```
StatusEffectView { int Id; string VfxAddress; }
```

- 클라 전용(Luban group `c`). 서버는 연출을 모른다.
- 키 = 상태이상 id. 마스터데이터 기본키 규약(정수 id)에 맞다.
- **`VfxAddress`가 비면 연출 없음** — 새 상태이상을 추가할 때 연출을 나중에 붙여도 안전하다.

### 연출 — `StatusEffectVfxView` (신규 클라 컴포넌트)

**어디에 두나**: `LOPEntityView`가 아니라 **별도 MonoBehaviour**로 뺀다.
`LOPEntityView`는 애니메이터 하나를 걷기·시전이 나눠 쓰는 한 덩어리인데, VFX는 애니메이터와 무관하다.
네임플레이트·데미지 숫자도 이미 각자 별도 컴포넌트라 그 결에 맞는다. `EntityBinder`가 캐릭터 스폰 시
루트에 붙인다.

**동작 — 읽어서 맞추기(pull)**

매 프레임 `World.Entity`의 `StatusEffects.Effects`를 읽어, *있어야 할 VFX 집합*과 *지금 켜둔 집합*을
맞춘다. 새로 생긴 것만 켜고, 사라진 것만 끈다. 걷기 애니(`UpdateRunAnimation`)와 같은 방식이며,
연속 상태를 이벤트가 아니라 pull로 다루는 프로젝트 표준(`world-core-connection-architecture.md`)에 맞다.

헤이스트와 슬로우가 동시에 걸리면 **둘 다 켜진다** — 상태이상 하나당 VFX 하나.

**붙는 자리**: 엔티티 **루트**(`Actor_{id}`)의 자식. 모델(스킨) 아래에 붙이면 스킨 교체 시 딸려
파괴된다. 루트는 시뮬 바디라 위치가 곧 캐릭터 위치다.

**비동기 로딩 경합 (실제 위험)**

Addressables 로드는 비동기인데 슬로우는 30틱(≈1초)이라, **로딩이 끝나기 전에 상태이상이 풀릴 수 있다.**
- 로딩 중인 항목을 자리에 표시해 **같은 효과를 중복 로드하지 않는다.**
- 로딩이 끝났을 때 그 효과가 **아직 붙어 있는지 다시 확인**하고, 아니면 즉시 버린다.
- 캐릭터 모델 로딩(`LOPEntityView.UpdateVisual`)이 이미 같은 모양의 방어를 한다.

**정리**: 엔티티가 죽거나 사라질 때 켜둔 VFX와 Addressables 핸들을 모두 해제한다(`ICleanup`).

## 검증

| 대상 | 방법 |
|---|---|
| `TargetType` 분기 | LOP-Shared EditMode — 순수 로직이라 TDD 선행 |
| `ApplyAuthoritativeState` | LOP-Shared EditMode — 추가/제거/스택변경/모디파이어 정리 |
| 데이터 | 마스터데이터 로드 + `TableFiles` 목록 EditMode 테스트 |
| 와이어·소유자 동기화 | 인게임 — EditMode로는 잡히지 않는 배선 |
| 연출 | 인게임 — 클라 코드는 `Assembly-CSharp`라 EditMode 불가 |

**인게임 최종 확인**

1. 헤이스트 발동 → **내 몸에 노란 이펙트**, 100틱 뒤 사라짐
2. 상대를 때림 → **상대 몸에 파란 이펙트**, **내 몸엔 안 뜸** (= `TargetType`이 동작한다는 증거)
3. **몬스터에게 맞음 → 내 몸에 파란 이펙트 + 내가 느려짐. 러버밴딩(뒤로 끌림) 없음**
   (= 소유자 동기화가 동작한다는 증거. 이번 슬라이스에서 가장 깨지기 쉬운 지점)
4. 헤이스트 중에 맞음 → **둘 다 동시에** 보임
5. 슬로우가 풀리기 전에 캐릭터가 죽음 → 이펙트가 남지 않음(정리 확인)
6. 원격 캐릭터에서도 1~4가 동일하게 보임
7. 회귀 — 이동·공격 모션·넉백·데미지 숫자가 이전과 같음
