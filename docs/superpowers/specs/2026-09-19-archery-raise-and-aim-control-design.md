# 활쏘기 조작 — 들어 올려 겨누기 (raise & aim)

**날짜**: 2026-09-19
**범위**: LeagueOfPhysical-Client (조작 UI), LeagueOfPhysical-Shared (당김 속도 상수)
**웹 프로토타입**: https://claude.ai/code/artifact/aa24c79f-3734-4551-8d76-0054b607da51 — 세 조작을 쏴 보고 고른 결과다

---

## 1. 왜

활쏘기의 실력 축을 **조준**으로 잡았는데, 조작이 그걸 못 받치고 있었다. 실물 판정이 세 번 같은 곳을
가리켰다:

| 실물 판정 | 밝혀진 원인 |
|---|---|
| *"조준에 실력 차를 내기 어렵다"* | 카메라가 속도를 쌓는 방식이라 **겨눈 곳에 멈출 수가 없었다**(떼도 5.2° 미끄러짐). 09-19에 `AimBy`로 고침 |
| *"뭐가 바뀐지도 모르겠다"* | 조준선이 착탄점을 그려 줘서 **겨눠서 멈출 일 자체가 없었다**. 09-19에 걷어냄 |
| *"손가락 하나로 힘과 조준을 같이 할 순 없나"* | **이 문서** |

지금 조작은 손가락이 **힘에 묶여 있다**. 오른쪽 절반에서 끈 거리가 곧 당김이라, 겨누는 일이
`WASD`로 밀려나 있다. 모바일에서는 두 손가락(왼쪽 시점 + 오른쪽 당김)을 요구한다.

---

## 2. 결정 — 힘을 손에서 뗀다

**덜 당긴 화살을 고를 이유가 없어졌다.** 화살을 150m/s로 올리면서(09-19) 부분 당김은 느리고 더
떨어지는 **그냥 나쁜 화살**이 됐다. 65m/s 시절엔 힘 조절이 곧 사거리 조절이라 의미가 있었지만
지금은 **언제나 만작이 정답**이다.

그러면 손가락을 힘에 묶어 둘 이유가 없다. 손가락이 하는 일은 둘뿐이다:

```
누르기        → 활이 올라온다 (0.5초에 만작, 힘은 늘 최대)
누른 채 움직임 → 겨눈다        (올라오는 동안에도)
떼기          → 발사
아래 띠로 내려 떼기 → 안 쏜다  (내려놓기)
```

### 2.1 왜 "취소"는 남기고 "힘 되돌리기"는 버리나

| | 남기나 | 왜 |
|---|---|---|
| 힘 되돌리기 | ✗ | 부분 당김이 전략이 아니게 됐다. 남기면 **내용 없는 의례**가 된다 |
| 취소 | ✓ | 화살이 정해진 수만큼뿐이라 **실수로 한 발 날리면 실제 손해**다 |

한때 "만작까지 끈 거리로 당기고 거기서 걸린다(앵커)"를 검토했으나 **기각**한다. 힘이 어차피 늘
최대라 그 드래그가 하는 일이 없다 — 취소 장치를 힘 조절인 것처럼 포장한 모양이었다.

### 2.2 산업 표준 매핑

젤다(BotW/TotK)의 활이 **드는 입력과 쏘는 입력이 다르다**(ZL로 들고 ZR로 쏘고, ZL을 놓으면
내려놓는다). 그래서 취소가 공짜다. 손가락 하나로 옮기면 "떼기 = 발사"가 되므로, 내려놓기는
**제스처**로 줘야 한다 — 그게 아래 띠다.

## 3. 무엇이 어떻게 바뀌나

### 3.1 당김 — 규칙은 시뮬에 둔다

`ArcheryAimSystem.Tick`은 **이미** 속도 제한을 걸어 당김을 올리고 있다:

```csharp
float drawTarget = command.Drawing ? command.DrawRatio : 0f;
float drawSpeed  = drawTarget > aim.DrawRatio ? DrawRisePerSecond : DrawFallPerSecond;
aim.DrawRatio    = Mathf.MoveTowards(aim.DrawRatio, drawTarget, drawSpeed * tickInterval);
```

그래서 바뀌는 것은 **두 곳뿐**이다:

| 무엇 | 지금 | 바꾼 뒤 |
|---|---|---|
| 화면이 보내는 `DrawRatio` | 손가락이 끈 거리(0~1) | **잡고 있으면 늘 1** |
| `ArcheryAimSystem.DrawRisePerSecond` | `10f` (0.1초 만작) | **`2f`** (0.5초 만작) |

`DrawFallPerSecond`(3f)는 그대로 둔다 — 쏜 뒤 줌이 한 프레임에 튀지 않게 하는 값이고 여전히 필요하다.

> **⚠️ 화면이 당김 속도를 정하면 안 된다.** 클라(예측)와 서버(권위)가 각자 `Tick`을 돌려 같은 값을
> 내놔야 발사 방향과 힘이 일치한다. 화면이 제 시계로 램프를 계산해 보내면 프레임레이트가 다른
> 두 기기가 서로 다른 화살을 쏜다. **화면은 "잡고 있다"만 말하고 얼마나 당겨졌는지는 시뮬이 정한다.**

**덤 — 서버가 클라의 숫자를 안 믿게 된다.** 지금은 힘이 클라가 보낸 `DrawRatio`에서 출발한다(속도
제한이 상한을 씌우긴 한다). 바꾸면 `DrawRatio`가 잡고 있는 동안 상수 1이라, **힘이 양쪽의 틱 수로만
정해진다** — 클라가 고를 수 있는 크기가 없다.

### 3.2 조준 — 오늘 만든 경로를 그대로 쓴다

같은 포인터의 이동을 `ArcheryPadViewModel.LookBy(화면 대비 비율)` → `CameraController.AimBy(도)`로
넣는다. 09-19에 만든 **관성 없는 경로**라 부른 만큼만 돌고 떼면 선다. 화각 보정이 이미 붙어 있어
**당길수록(화면이 좁아질수록) 저절로 정밀해진다** — 당김과 조준이 한 손가락에 있으니 특히 잘 맞는다.

바뀌는 것은 *누가 부르느냐*뿐이다: 왼쪽 절반 전용 → **당기고 있는 그 포인터**.

### 3.3 취소 — 누른 자리 아래의 원 (2026-09-20 개정)

- 잡고 있는 **동안에만**, **누른 자리에서 아래로 약 20mm**에 지름 10mm의 원이 보인다.
- 자리는 **누를 때마다 새로 잡히고**, 그 누름 동안은 고정이다(손가락을 따라다니면 영영 못 닿는다).
- 손가락이 원 안에 들어오면 **테두리만 붉어진다.** 활은 안 내려가고 조준도 안 멈춘다.
- **판정은 뗄 때만** 한다 — 원 안에서 떼면 `SetRelease()`를 아예 안 보낸다(기존 경로 그대로).
- 취소하면 조준을 **활 들기 직전 자리로** 0.18초에 걸쳐 되돌린다(뗀 *뒤에* 돈다).

| | 값 | 화면 세로를 1로 본 값 |
|---|---|---|
| 누른 자리에서 아래로 | 20mm | `CancelBelowPressInHeights = 0.31` |
| 반지름 | 5mm (지름 10mm) | `CancelRadiusInHeights = 0.075` |

**왜 이 자리인가.** 당긴 상태(화각 22°)에서 조준이 실제로 도는 거리는 홀드오버 1.12° +
미세조정 ±3° = 화면 세로의 **14% 남짓**이다. 원의 안쪽 가장자리가 23.5%라 그 밖이다.
누른 자리 기준이라 **엄지가 갈 거리가 늘 같다**.

> **⚠️ 첫 실물 확인 항목.** 과녁이 누를 때보다 훨씬 아래 있으면 **조준을 끝낸 자리가 원 안**일 수
> 있고, 쏘려다 취소된다. 원이 덮는 구간은 아래로 **5.2°~8.5°**다. 걸리면 거리를 늘리거나
> "0.15초 머물렀다 떼야 취소"를 더한다.

#### 왜 띠(화면 아래 15%)를 버렸나

원래는 화면 **아래 15%**를 띠로 썼다. 실물에서 세 가지가 드러났다:

1. **아래로 겨누는 것과 취소가 같은 동작이었다.** 띠에 들어가는 *순간* 활이 풀리고 조준이 멈춰,
   낮은 곳을 겨누려 내려가면 취소됐다. 취소가 조준을 들기 직전으로 되돌리니 **무한 루프**가 됐다.
2. **띠까지 가는 거리가 제멋대로였다.** 화면 위쪽에서 누르면 35mm, 아래쪽에서 누르면 0mm.
3. **가로 화면에서 엄지가 쉬는 자리가 띠 안이었다.** 거기서 눌러 시작하면 가만히 있으면 발사,
   조금이라도 움직이면 취소 — 손 떨림 하나로 갈렸다.

#### 산업 표준 매핑

- **Wild Rift**(스킬 취소 X를 스킬 버튼 옆에) — *취소 타깃은 그 조작을 하는 엄지 근처에 둔다.*
  단 구조가 다르다: 거기선 드래그가 카메라가 아니라 **사거리 안의 한 점**이라 유한하고, 원 밖이
  곧 "조작이 안 쓰는 땅"이다. 우리는 드래그가 카메라라 그런 땅이 없어 **14%라는 선을 그어 만들었다.**
- **iOS·Android 버튼 / WCAG 2.5.2 Pointer Cancellation** — *누르는 순간이 아니라 **떼는 순간**이
  결정한다.* 위 ②가 이것이다.
- **Genshin 모바일**(드래그로 겨누고 **공격 아이콘 탭으로 발사**) — 우리와 같은 무한 카메라
  드래그인데, **떼기를 발사에서 떼어** 문제를 구조적으로 없앴다. 아래 §7 참고.

### 3.4 캡처를 뺏기면 쏘지 않는다

`PointerCaptureOut`(손가락이 화면 밖으로 나가거나 OS가 터치를 가져갈 때 — 알림 스와이프·전화·앱
전환)이 **발사 판정으로 가고 있었다.** 터치를 뺏긴 건 "쏘겠다"는 뜻이 아니고 화살은 유한하므로
**내려놓기로 보낸다**(`ArcheryPadViewModel.Cancel()`).

### 3.5 사라지는 것

- **당김 게이지** — 손가락 자리에 그리던 바깥 원·임계치 원·손잡이(`draw-gauge` 일체). 끈 거리가
  당김이 아니게 되므로 그릴 것이 없다.
- `FullDrawDragFraction`, `DrawOrigin`/`DrawCurrent`/`FullDrawPixels`, `DragDraw` — 그 게이지의 부속.

당김은 이제 **줌**(60°→22°)과 **조여드는 조준점**으로 읽힌다. 둘 다 이미 있다.

### 3.6 남기는 것

- **WASD 조준** — 활을 걸지 않고 둘러볼 때 쓸 데가 있고 비용이 0이다.
- 왼쪽/오른쪽 절반 구분은 **없앤다** — 화면 아무 데나 눌러 시작한다(띠 제외).

## 6. 실물 확인

1. **누르는 순간 조준점이 안 튄다** (누른 자리에서 이어진다)
2. **올라오는 0.5초 동안 이미 겨눌 수 있다** — 움직이는 과녁에서 이게 핵심이다
3. **띠로 내려 떼면 화살 수가 안 준다**
4. **아래로 겨누다 실수로 취소되지 않는다** (§3.3의 위험) — 특히 12m·20m 같은 낮은 과녁
5. 짧게 톡 쳐도 안 나간다(0.075초 미만)

## 7. 검토했고 지금은 안 하는 것

| 안 | 무엇인가 | 왜 지금은 아닌가 |
|---|---|---|
| **떼기를 발사에서 뗀다** (Genshin 구조) | 화면 드래그로 겨누고(떼도 조준 유지) 오른쪽 아래 **발사 버튼 탭**으로 쏜다 | 취소 문제가 **구조적으로 소멸**한다. 대신 **활시위를 놓는 손맛이 사라진다** — 되돌리기 어려운 감각 변경이라, 위 원이 실물에서 정말 걸리는지 보고 간다 |
| **두 번째 손가락으로 취소** | 화면에 손가락을 하나 더 대면 내려놓기 | 왼쪽 엄지는 **장차 이동 스틱**이 쓴다. 왼손을 못 뗀다 |
| **왼쪽에 취소 버튼** | 스틱 위 ~20mm에 작은 버튼 | 위와 같은 이유로 왼손이 스틱을 떠나야 한다. 오른손만으로 끝나는 위 안이 낫다 |
| **피로 — 오래 버티면 저절로 내려간다** | 만작 유지에 시간 제한 | 손가락도 화면도 안 쓰는 취소가 덤으로 생기지만 **게임 규칙**이라 시뮬(`ArcheryAimSystem`) 변경 + 게임서버 재빌드가 붙는다. 별도 슬라이스 |

## 8. 여기서 정하지 않는 것

- **과녁 컨셉**(정지 / 러닝 타겟 / 다가오는 과녁 / 진자) — 새 조작 위에서 다시 쏴 보고 정한다.
  조작이 바뀌면 움직이는 과녁의 느낌이 같이 바뀌기 때문이다.
- 취소 원의 정확한 거리·크기 — 첫 실물에서 §6-4를 보고 조정한다(20mm / 지름 10mm가 시작값).
  **줄일 수 있는 바닥은 지름 7~8mm**(애플 44pt·구글 48dp). 값이 화면 **비율**이라
  에디터 Game 뷰에서는 크게 보이는 것이 정상이다 — 판정 기준이 각도라 비율이어야 한다.
- 모바일 실기기 확인 — APK 파이프라인이 있지만 이번 슬라이스에 넣지 않는다.
